## Asset Workflow

A portfolio project accumulates thousands of image files across dozens of events.
Without a convention this becomes unnavigable within months: nobody knows which
`hero-final-v3-USE-THIS.jpg` is current, the repository is four gigabytes, and a
clone takes twenty minutes.

**Two rules carry most of the value:** one master per published image, and
derivatives are never committed.

> **Before running anything:** confirm with the client where the *true* masters
> live — a photographer's Drive, a hard disk, a shared album. The repository holds
> working copies, not the archive of record.

### Method

1. **Separate archive, masters, and derivatives.**
2. **Adopt one naming convention** and enforce it.
3. **Strip EXIF on ingest**, before anything is committed.
4. **Keep derivatives out of git** entirely.
5. **Record provenance** so an image can be traced to its source and consent.

### The three tiers

| Tier | Where | Committed | Size |
|---|---|---|---|
| **Archive** | Client's own storage. Full album, untouched | No | 10s of GB |
| **Masters** | `src/assets/events/<slug>/` — the selected 9–14, graded, EXIF-stripped, ≤2500 px long edge | **Yes** | 300 kB–1.5 MB each |
| **Derivatives** | `dist/_astro/` — every AVIF/WebP variant the build emits | **No** | Regenerated |

**Masters belong in `src/assets/`, not `public/`.** Anything under `src/assets/`
goes through the build pipeline and gets hashed, optimised filenames; anything in
`public/` is copied verbatim and is *not* optimised. Putting photographs in
`public/` silently bypasses every optimisation in `image-optimization`, and it is
the most common structural mistake in an Astro project.

`public/` is for `favicon.ico`, `robots.txt`, `og-default.jpg`, fonts, and video.

### Naming

```
src/assets/events/2026-02-sharma-wedding/
  01-establishing-venue-exterior.jpg
  02-detail-mandap-flowers.jpg
  03-human-bride-mother.jpg
  04-hero-varmala.jpg
  ...
  14-closing-vidai.jpg
```

- **Directory: `YYYY-MM-<client>-<event-type>`** — sorts chronologically, unique,
  readable.
- **File: `NN-<role>-<subject>.jpg`** — `NN` is sequence position, `<role>` is the
  `art-direction` role. The role in the filename means a reviewer can check role
  coverage with `ls`.
- **Lowercase, hyphens only.** Spaces and capitals cause case-sensitivity bugs
  between macOS and Linux CI — a real and annoying class of build failure.
- **No `final`, `v2`, `USE-THIS`, or dates in filenames.** Git holds versions.

```bash
# Role coverage at a glance
ls src/assets/events/2026-02-sharma-wedding/ | cut -d- -f2 | sort | uniq -c
```

### Ingest

Run once per event, before committing anything:

```bash
#!/usr/bin/env bash
# bin/ingest-event.sh <slug> <source-dir>
set -euo pipefail
slug="$1"; src="$2"
dest="src/assets/events/$slug"
mkdir -p "$dest"

for f in "$src"/*.{jpg,JPG,jpeg,png}; do
  [[ -e "$f" ]] || continue
  base=$(basename "${f%.*}" | tr '[:upper:] ' '[:lower:]-')
  magick "$f" -resize '2500x2500>' -quality 92 "$dest/$base.jpg"   # cap the master
  exiftool -all= -overwrite_original "$dest/$base.jpg"             # strip metadata
done

echo "Ingested to $dest — now rename to NN-<role>-<subject>.jpg"
exiftool -GPSLatitude -GPSLongitude "$dest"/*.jpg | grep -i gps && \
  { echo "GPS DATA REMAINS — do not commit"; exit 1; } || echo "✓ no GPS data"
```

**EXIF stripping is not optional.** Event photographs carry GPS coordinates of
private homes and venues, camera serial numbers, and timestamps. Publishing them
discloses a client's home address. The script fails loudly if any survives.

**Cap masters at 2500 px.** Larger gains nothing — the widest variant served is
2000 px — and it bloats the repository permanently, since git keeps every version
forever.

### Keeping git usable

```gitignore
# Derivatives — regenerated by the build
dist/
.astro/
node_modules/

# Never commit raw camera output
*.CR2
*.NEF
*.ARW
*.dng

# Video masters live with the host, not in git
public/media/*.mp4
public/media/*.webm
!public/media/.gitkeep
```

**Video does not belong in git.** Even one 30 MB file makes every clone slower
forever. Use Git LFS, or host video externally and reference it.

If the repository is already large, `git-filter-repo` can excise history — but it
rewrites hashes and requires everyone to re-clone. Set the convention up front.

### Provenance

Each event directory carries a small manifest tying images to their source and
their consent record:

```yaml
# src/assets/events/2026-02-sharma-wedding/_source.yml
event: "Sharma Wedding"
date: 2026-02-14
photographer: "Studio Kalpana"
photographerCredit: true         # must be credited on the page
archiveLocation: "Client Google Drive — Sharma Wedding Feb 2026"
ingestedOn: 2026-03-02
ingestedBy: "rb"
exifStripped: true
consentRecord: "src/content/events/sharma-wedding-2026.md#mediaConsent"
licence: "Client-owned; usage granted for studio.example and Instagram"
```

**Photographer credit is a licence condition more often than people assume.**
Record it at ingest, or it will not be honoured at publication.

### Detection

```bash
find public -name '*.jpg' -o -name '*.png' | head            # should be nearly empty
find src/assets -size +2M                                     # oversized masters
exiftool -GPSLatitude src/assets/events/*/*.jpg 2>/dev/null | grep -i gps
find src/assets -name '* *' -o -name '*[A-Z]*'                # spaces or capitals
find src/assets/events -type d ! -name '_*' -mindepth 1 -maxdepth 1 \
  ! -regex '.*/[0-9]\{4\}-[0-9]\{2\}-.*'                      # bad directory names
git count-objects -vH | grep size-pack                        # repo size
for d in src/assets/events/*/; do
  [[ -f "$d/_source.yml" ]] || echo "missing manifest: $d"
done
```

### Caveats

- **The repository is not the archive.** Make sure the client keeps the full
  album somewhere durable; a git repo of 14 selects is not a backup.
- **`magick` is ImageMagick 7.** On older installs the command is `convert`.
- **Stripping all EXIF removes the colour profile too.** Convert to sRGB before
  stripping, or images shift colour in some browsers:
  `magick in.jpg -colorspace sRGB -strip out.jpg`.
- **Renaming a master changes its build hash**, which busts caches and any
  external link to the old URL. Name it right at ingest.

### Checklist

- [ ] Archive, masters, and derivatives clearly separated
- [ ] Masters in `src/assets/`, never `public/`
- [ ] Directory `YYYY-MM-<client>-<event>`; files `NN-<role>-<subject>.jpg`
- [ ] Lowercase, hyphens, no version words in filenames
- [ ] Masters capped at 2500 px long edge
- [ ] EXIF stripped and verified — no GPS survives
- [ ] sRGB conversion before stripping
- [ ] Derivatives, raw formats, and video gitignored
- [ ] `_source.yml` manifest per event, including photographer credit
- [ ] Consent record cross-referenced
- [ ] Repo pack size checked and reasonable
